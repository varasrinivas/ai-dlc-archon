The idea. How your team works becomes a YAML workflow: a graph of nodes, some an AI agent with a prompt, some plain code, some a pause where a person decides. Archon runs it the same way every time, each run in its own worktree and branch, checks the agent's work with commands instead of taking its word, and keeps the transcript, the files each step wrote and the cost. It brings no model: it drives the agent you already use.

Workflow

WhatA YAML file that says how one kind of work is done: its nodes, the order, the checks and the pauses.

WhyThe process moves out of the model's head into a file the team owns, reviews and changes by pull request.

Analogy A recipe card pinned in the kitchen; every cook follows it.

.archon/workflows/<pack>/<name>/<name>.yaml · archon workflow list · validate workflows

Nodes: one job each

WhatOne step with one body: prompt/command (an agent), bash/script (code), loop/loop_group, wait, cancel, include/workflow.

WhyYAML coordinates, code computes, agents judge: the certain steps stay code, the agent gets the judgment calls.

Analogy A production line: skilled stations, machines, and an inspector's desk.

output_format = JSON reply, read as $plan.output.summary · mutates_checkout: false

The graph

Whatdepends_on orders nodes (no edge = parallel); when: skips a node unless a condition holds; trigger_rule joins parents.

WhyOne file holds every path (approved, rejected) without a script deciding at run time.

Analogy A wiring diagram; a switch decides which branch lights up.

when: "$approve-plan.output.decision == 'reject'" · --dry-run walks it free

Commands and packs

WhatA command is a Markdown prompt a command: node sends; a pack is a folder of workflows, each with its own commands/.

WhyLong prompts are reviewed and diffed like code, and two workflows' review.md never collide.

Analogy "Make the sauce, see card 12": card 12 sits in the recipe's own folder.

team pack: commands/scan.md, implement.md · not Claude Code's .claude/commands/

Loops and their checks

Whatloop repeats a step, loop_group a small graph, until until_bash exits 0 (or until_field, until), at most max_iterations.

Why"Until the tests pass" is only safe when code, not the model, decides it is done.

Analogy A driving test: three tries, and the examiner says when you pass.

implement: until_bash: ./scripts/verify.sh, max 3, fresh_context · passed in 1

Waits and the attention queue

WhatA wait: pauses the run durably until someone answers; form: message, approval, select, multi_select.

WhyPeople decide without a terminal hanging: a paused run holds no process and survives restarts.

Analogy A form in a manager's in-tray; the clerk carries on once it is signed.

workflow attention · wait <run> · reject does not cancel: route it

Runs

WhatOne execution: a 32-character id, a status, a JSONL transcript, tokens and cost, kept in archon.db.

WhyYou can always say what ran, what the agent was told and said, who answered, and what it cost.

Analogy A parcel's tracking number.

--detach · workflow runs · get · logs --format text · resume · abandon

A worktree per run

WhatEach run works in its own git worktree and branch under ~/.archon/workspaces/; your checkout stays as you left it.

WhySeveral runs can change the same files at once; a result you don't like is a branch you drop.

Analogy A builder draws on a copy of the plans, not the originals.

--branch · --no-worktree · isolation list · complete <branch> · not a sandbox

Artifacts and variables

WhatFiles a run writes to $ARTIFACTS_DIR, outside the repo; placeholders $USER_MESSAGE, $BASE_BRANCH, $<node>.output.

WhyNodes hand work over through files, so a fresh session reads just plan.md and stays focused.

Analogy The surveyor's folder of working papers; the house gets only the work.

scan.md … review.md · workflow artifacts <run> <file> · never in git

Providers and tiers

WhatArchon runs the agent you have (Claude Code, Codex, Pi) with your login; a tier names a provider and model.

WhyThe team keeps its agent and its CLAUDE.md; cheap steps can use a cheaper model.

Analogy A staffing agency: Archon books the work, your agencies send the people.

assistant: claude · small = haiku · medium = sonnet · large = opus · ai tier list

Where things live

WhatThe repo's .archon/ (workflows, config: shared, committed) and your ~/.archon/ (binary, plugins, archon.db, workspaces: yours).

WhyThe process travels with the code; the runs stay on the machine that ran them.

Analogy The cookbook in the restaurant; each cook's notebook in their locker.

repo config wins over home · credentials in .env · first run registers the project

Surfaces and the sdlc pack

WhatStart and answer runs from the CLI, the Web UI (archon serve, :3090), chat or triggers. 25 bundled workflows: archon-ship and its queues.

WhyA decision reaches whoever can make it; the pack shows what a full process looks like.

Analogy A shop with a counter, a website and a phone; a car plant next to your garage.

archon-plan, -investigate, -review alone · the factory needs gh and CI

Easy to mix up

run ≠ workflow ≠ command

one execution · the YAML process · one prompt file a node sends

wait ≠ cancel ≠ reject

a pause · a node that ends the run · an answer the YAML must route

loop ≠ loop_group ≠ retry

repeat one step · repeat a small graph · run a failed node again

worktree ≠ sandbox ≠ branch

a second checkout · isolation it doesn't give · what the worktree is on

artifacts ≠ the repo

per-run papers in ~/.archon · only the code and tests

Five myths

"Reject stops the run." Only where a cancel: node says so.

"It's an AI model." It is an engine that runs your agent.

"The worktree keeps the agent safe." It keeps your checkout clean; it is not a sandbox.

"Old workflow names still work." 0.12.0 removed archon-fix-github-issue and others.

"Telemetry is off." It is on: ARCHON_TELEMETRY_DISABLED=1.

At a pause you type

archon workflow attention (what waits) · answer <run> --occurrence <id> --text "…" · approve <run> "why" · reject <run> "what to change" · respond <run> <option>

From run to PR · OURS

One run = one branch (--branch). Push from the workflow or by hand, open the PR, merge; then archon complete <branch>. A follow-up fix: archon-implement --adopt <run>.
