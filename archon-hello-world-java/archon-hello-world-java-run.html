In plain words. AI-DLC gives you a method with its stages and record already decided. Archon gives you an engine and asks you to write the method down. The same team rules (CLAUDE.md, one verify script, people approve) worked in both.

Run it yourself

  1. Install Archon and the Claude provider, and check with archon doctor (setup page, steps 1–4).
  2. Clone the starter with --no-tags and write the team's files (setup page, steps 5–8), or copy them from archon-hello-world-java/java-workspace/ in the course files, which is the repo at the end of this run.
  3. Start the run as in step 4 and answer each wait. Your questions and wording will differ: the agent is not deterministic. Use the answers from steps 5–8 so the requirements land where the course's did.
  4. Compare with java-workspace/: the code, the tests (24), and the curl numbers in step 13.
Your run ids, times, costs and commit hashes will differ. The course's transcripts are in java-run/logs/ and its artifacts in java-run/artifacts/.

Ten words

workflow
the YAML file with the team's process (request-to-pr)
node
one step of it: an agent prompt, a bash command, a loop or a wait
run
one execution, with a run id
wait
a node that pauses the run until someone answers
form
what a wait accepts: message, approval, select
attention queue
every run that is waiting for someone
loop_group
a few nodes repeated until a check passes; here, until the requirements are approved
until_bash
the shell check that ends a loop on exit 0
worktree
the run's own checkout, on its own branch, under ~/.archon
artifacts
the files a run writes for people and later nodes: scan.md, requirements.md, plan.md…
