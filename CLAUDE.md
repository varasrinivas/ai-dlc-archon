# CLAUDE.md

Guidance for Claude Code when working in this folder.

## What this folder is

An Archon course (coleam00/Archon 0.13.2, the YAML workflow engine for AI coding, run with Claude Code), a sibling of `../ai-dlc-execution` (the AWS AI-DLC course) and built the same way: self-contained static HTML pages generated by Python scripts from real, captured output. The only external dependency of a page is Google Fonts. `index.html` is the hand-written hub.

| Page | Generator | Built from |
|---|---|---|
| `archon-introduction.html` | `tools/build_intro_page.py` | `tools/data/cli/cli.json`, the team workflow, `java-run/steps.json` |
| `archon-concepts-explained.html` | `tools/build_concepts_page.py` | the Archon 0.13.2 docs, the team workflow, `cli.json` |
| `archon-concepts-onepage.html` (A4 landscape cheat sheet, same design as `aidlc-concepts-onepage.html`) | `tools/build_onepage.py` | the concepts page's content condensed; asserts node kinds, tiers, bundled count, the run's commands |
| `archon-concepts-map.svg` (standalone, fixed light colours, like `aidlc-concepts-map.svg`) | `tools/build_concept_map.py` | the team workflow (node ids, kinds, loop checks), `inventory.json` (`~/.archon` layout), the run's artifacts |
| `archon-workspace-setup.html` | `tools/build_setup_page.py` | `install.txt`, `cli.json`, `home-config.yaml`, `inventory.json`, `java-run/setup-steps.json`, `tools/data/setup/`, `img/webui-*.png` |
| `archon-hello-world-java/archon-hello-world-java-run.html` | `tools/build_run_page.py` | `archon-hello-world-java/java-run/` and `java-workspace/` |

Edit the generators, never the HTML. Each generator asserts the numbers it prints (bundled workflow count, node and wait counts, test counts, costs, the review verdict, the curl output), and `pagekit.write()` fails if a local path (your user folder, `D:\tmp`, the hostname, the Claude projects slug; `pagekit` reads the user and hostname from the machine, so neither is written in the repo) leaks onto a page. Rebuild all: `for p in intro concepts setup run; do py -3.12 tools/build_${p}_page.py; done; py -3.12 tools/build_onepage.py; py -3.12 tools/build_concept_map.py`. The sheet's text has no room to spare: after changing it, check in a browser that no `.tile` overflows (`scrollHeight > clientHeight`).

## Shared pieces

- `tools/frame/style.css`, `script.js` are the AI-DLC run page's frame, and `concepts.css`, `concepts.js` are the AI-DLC concepts page's. `tools/make_frame.py` copies them from `../ai-dlc-execution`, renames the phase colours to Archon's (`--setup --plan --build --review --ship`) and the localStorage keys (`arc-*`), adds `jsonl` to the highlighter. Re-run it only to pick up a change in the AI-DLC frame.
- `tools/pagekit.py` holds the step-page helpers (`step`, `you`, `see`, `disk`, `gate`, `tabs`, `table`, `rail`, `page`), `scrub()` (maps local paths to `C:\Users\you` / `C:\work\archon-java`) and the leak check. Every shell command shown needs a Windows and a macOS variant (`you(win, mac)`); the macOS ones are documented, not run.
- `tools/diagrams.py` draws the workflow graph from the YAML (parsed by `tools/cli_parse.py`) and the node-cycle figure, in theme tokens.
- `tools/team_files.py` (copied from the AI-DLC course) writes files inline as PowerShell here-strings / heredocs: the setup page's step 6.

## The team's files and the run

`tools/data/java/files/` are the team's files written into the starter repo: `CLAUDE.md`, `.gitattributes` (keeps `verify.sh` LF in worktrees; needed because this machine has `core.autocrlf=true`), `scripts/verify.{sh,cmd}`, `docs-in/request.md` (copied from the AI-DLC course), `.archon/config.yaml`, and the packaged workflow `.archon/workflows/team/request-to-pr/` (15 nodes, 4 waits; `commands/scan.md`, `implement.md`). If you change one, re-run the setup and the run, or the pages will disagree with the files.

The real run (3 Nov 2026, Archon 0.13.2, Claude Code on the claude.ai login, Windows):
1. `py -3.12 tools/setup_java_run.py` rebuilds `D:\tmp\archon-java`: `origin.git` (bare, public starter `main` = v1.0.2, no tags) standing in for GitHub, and Kiran's clone `priorauth-api` with the team files committed and pushed; records `tools/data/java/setup-steps.json`.
2. Each command of the run went through `py -3.12 tools/archon_step.py tools/data/java/run-steps.json <label> <cwd> -- <cmd>` (or `--sh "<bash>"`). It removes `ANTHROPIC_API_KEY` (claude.ai login only), sets `ARCHON_TELEMETRY_DISABLED=1`, puts JDK 21 first on PATH (the machine default is 11) and sets `ARCHON_BASH_PATH` (Git is on D:, which Archon does not autodetect). Labels the page reads: `dry-run run wait-1 answer-1 reject-requirements approve-requirements approve-plan reject-change fix-run package curl push-by-hand runs get artifacts isolation-list checkout-untouched archon-plan plan-finish logs-text complete isolation-after artifacts-after remote-branch merge complete-after-merge isolation-final verify-main`.
3. `py -3.12 tools/capture_java_run.py` copies steps, transcripts, artifacts, per-node timings/costs (`nodes.json`), git graph and per-commit patches (base `main^1`, since main now has the merge), and `git archive` of the branch into `archon-hello-world-java/java-workspace/`.
4. `py -3.12 tools/capture_cli.py <archon-source-clone>` captures help, doctor, telemetry, workflow list (+ every bundled `--full`), validate, tiers, plugins, isolation, runs, the `~/.archon` inventory, and copies the sdlc pack YAML from a v0.13.2 clone into `tools/data/cli/bundled/`.
5. `py -3.12 tools/scrub_captures.py` after any capture or `archon_step.py` call: in `tools/data/` and `java-run/` it maps the user folder, `D:\tmp`, the hostname and Claude scratchpad paths to `C:\Users\you`, `C:\work`, `your-pc` (idempotent; `--check` exits 1 if anything is left or would change). Pages don't change: `pagekit.scrub()` already maps the same paths at build time. `D:\Program Files\Git` is kept on purpose: Git being on D: is the bash finding.

What happened (the pages tell it; keep them consistent): the questions node asked 6 questions; Kiran answered for Ravi and Meena; Meena rejected requirements revision 1 with the screen team's names (`ageBusinessDays`, `overLimit`, `ageLabel`, `priorauth.aging.threshold-days`, `data/holidays-<tenant>-<year>.json`, as-of before received = 400); approved revision 2; approved the plan; the implement loop passed `verify.sh` in 1 iteration (commit `f3a465d`, 21 tests); the review node returned NOT-READY (R-1: unbounded `asOf`, e.g. `+999999999-12-31`); Meena rejected, `stop-change` cancelled the run (the CLI misleadingly printed "Rejected but failed to resume … bun run cli workflow resume"); `archon-implement --adopt <run>` (claude/opus via the default `large` tier) fixed R-1/R-2 (`d6288f5`, 24 tests); Kiran checked the jar by hand (7 OVER 5 / 4 / 1, same as AI-DLC v1.1.0; huge asOf → 400) and pushed; `archon complete` refused before the merge (2 unmerged commits; skipped its gh PR check), Meena's `git merge --no-ff` stood in for the PR merge, then `complete` removed the worktree and kept the remote branch. Then `archon-plan --no-worktree` on the same request paused as one attention item (rule not in the repo, existing branch noticed) and was ended with `respond finish`. Reported cost: $3.31 request-to-pr, $0.58 the fix (API-price equivalents; claude.ai plan). Not run: opening the PR (no `gh` login).

Other measured findings shown on the pages: bash nodes fail with "bash executable not found" when Git Bash is elsewhere (`tools/data/setup/bash-probe.json`; validate doesn't catch it); `validate workflows` warns `bun` missing for 24 bundled workflows on Windows yet their script nodes ran; `archon serve` listens on 0.0.0.0 with no auth on a solo install, downloads a 92 MB server + 1.8 MB UI (`tools/data/setup/serve.json`); Web UI screenshots in `img/` have display paths mapped in the browser before capture and the scratch project hidden.

Cast and story match the AI-DLC course on purpose: Ravi Menon (nurse manager), Kiran Rao (developer), Meena Iyer (tech lead), Ravi's Slack request of Tue 13 Oct; the run itself happened 3 Nov 2026.

## After an Archon update

Re-run steps 1–5 above in an empty `D:\tmp` (a full run takes about 30 minutes and several Claude sessions; answer the waits with the same text, read from the old `steps.json`), re-capture, rebuild, and fix whichever assert breaks. Also re-check: workflow names (0.13.1 made them exact), the node-kind list, the `archon help` command count, and the bash/bun/serve findings.
