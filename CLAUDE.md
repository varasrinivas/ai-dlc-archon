Guidance for Claude Code when working in this folder.

## What this folder is

An Archon course (coleam00/Archon 0.13.2, the YAML workflow engine for AI coding, run with Claude Code), a sibling of `../ai-dlc-execution` (the AWS AI-DLC course) and built the same way: self-contained static HTML pages generated by Python scripts from real, captured output. The only external dependency of a page is Google Fonts. `index.html` is the hand-written hub.

Edit the generators, never the HTML. Each generator asserts the numbers it prints (bundled workflow count, node and wait counts, test counts, costs, the review verdict, the curl output), and `pagekit.write()` fails if a local path (your user folder, `D:\tmp`, the hostname, the Claude projects slug; `pagekit` reads the user and hostname from the machine, so neither is written in the repo) leaks onto a page. Rebuild all: `for p in intro concepts setup run; do py -3.12 tools/build_${p}_page.py; done; py -3.12 tools/build_onepage.py; py -3.12 tools/build_concept_map.py; py -3.12 tools/build_multirepo_page.py; py -3.12 tools/build_aidlc_map_page.py; py -3.12 tools/build_guide_page.py`. The sheet's text has no room to spare: after changing it, check in a browser that no `.tile` overflows (`scrollHeight > clientHeight`).

## Shared pieces

- `tools/frame/style.css`, `script.js` are the AI-DLC run page's frame, and `concepts.css`, `concepts.js` are the AI-DLC concepts page's. `tools/make_frame.py` copies them from `../ai-dlc-execution`, renames the phase colours to Archon's (`--setup --plan --build --review --ship`) and the localStorage keys (`arc-*`), adds `jsonl` to the highlighter. Re-run it only to pick up a change in the AI-DLC frame.
- `tools/pagekit.py` holds the step-page helpers (`step`, `you`, `see`, `disk`, `gate`, `tabs`, `table`, `rail`, `page`; `shell_group` renders recorded setup commands with `cd` lines and their output), `scrub()` (maps local paths to `C:\Users\you` / `C:\work\archon-java`) and the leak check. Every shell command shown needs a Windows and a macOS variant (`you(win, mac)`); the macOS ones are documented, not run.
- `tools/diagrams.py` draws the workflow graph from the YAML (parsed by `tools/cli_parse.py`) and the node-cycle figure, in theme tokens.
- `tools/team_files.py` (copied from the AI-DLC course) writes files inline as PowerShell here-strings / heredocs: the setup page's step 6.

## The layout: a team workspace around the code repos

Every tutorial uses the AI-DLC course's layout: a **team workspace** (a git repo of its own with `.archon/`, `CLAUDE.md`, `scripts/verify.*`, `docs-in/`, and a `.gitignore` that leaves the code repos out) with the code repos cloned inside it. Archon runs it as a **folder project** (`--folder` on the first run, from the workspace root): in place, no worktree, no branch or PR from Archon; the agent branches and commits in each code repo, and the workflow's bash nodes use `git -C <repo>`. The pages present the other layout (`.archon/` inside one repo, a worktree per run, `--branch`, `archon complete`) as documented, not run (intro step 7's comparison table, the concepts page's `worktrees` card).

The course repo carries both workspaces as real, buildable files (git archive of each repo's `main` after the merge, no `.git`): `archon-hello-world-java/java-workspace/` (with `priorauth-api/`) and `archon-hello-world-java/multirepo-workspace/` (with `priorauth-aging/` and `priorauth-api/`). Each one's own `.gitignore` ignores its code repos, so **the course commits them with `git add -f`** (tracked files are not affected by ignore rules, but new files are), and `verify.sh` is marked `git update-index --chmod=+x`. Check after a re-capture: copy each to a temp folder, `git init`, `archon validate workflows <wf>` and `./scripts/verify.sh` with JDK 21 (21 tests and 14 tests).
